# 06 · 前端展示与作品交付体验

> 状态：需求收集阶段。本文档记录前端美观/设计要求、开源模块复用评估、排队展示与「作品完成」交付体验方案。

## 一、设计总体要求

- **移动端优先**：入口是企微聊天卡片，顾客全部在手机上操作
- **气质要求**：花艺 = 审美生意，页面必须「显得贵」：大图、留白、慢动效、克制配色
- 品牌视觉素材（logo、主色、字体、作品摄影图）由商家提供，作为设计基准

## 二、开源模块复用评估

### 结论：零部件用现成的，整体系统自己搭

| 部件 | 方案 | 成熟度 |
|---|---|---|
| 移动端 UI 组件库 | Vant（Vue 系）或 Ant Design Mobile（React 系），待技术选型定稿后匹配 | ✅ 极成熟，亿级用户验证 |
| 分步表单 | 组件库自带 Steps + Form + Field | ✅ 现成 |
| 图片上传 | 组件库 Uploader + 对象存储直传 | ✅ 现成 |
| 图片轮播/大图预览 | 组件库自带 | ✅ 现成 |
| 微信支付 | 微信官方 SDK（不用第三方封装） | ✅ 官方维护 |
| 排队/等待时长展示 | 无现成模块，自研（逻辑简单：按已付订单计数） | 🔨 自研，量小可控 |

### 明确不采用：开源商城系统（CRMEB、NiuShop 等）

理由：为标准卖货设计，体量重、样式难改；花艺定制需要的「仪式感页面」这类系统做不出来，二次开发成本高于自建。

> 该结论同时符合「防 AI 幻觉」策略：主流组件库语料充足，AI 生成质量高、错误率低。

## 三、付款前：排队/等待信息展示

顾客在**选套餐页/付款确认页**即可看到实时排队情况：

- 今日/本月已预订人数
- 当前排到第几号
- 预计等待时长（如「预计 5~7 天交付」）

实现：后端按已付款订单统计即可，无需复杂队列系统。
✅ 已确认（v0.3）：**每日限量接单，当日名额满后自动顺延到下一日**；每日上限数字待商家提供。
展示逻辑：顾客选套餐时看到「今日还剩 N 个名额 / 最早可排 X 月 X 日」。

## 四、「作品完成」交付体验（本项目差异化重点）

### 流程

```
作品制作完成
    │
    ▼
商家后台上传：成品摄影图 + 抖音视频链接 + 直播预告(可选)
    │
    ▼
服务号模板消息推送：「您的专属花艺作品已完成 🌸」
    │
    ▼
顾客点开 → 专属「作品诞生页」：
    ├─ 成品大图轮播（摄影级呈现）
    ├─ 专属作品编号 + 定制信息回显（花种/色系/参考图对照）
    ├─ 「观看抖音摄影大片」跳转按钮
    ├─ 直播间预告/跳转（可选）
    └─ 引导语：晒图/分享（自带传播）
```

### 设计关键词

- 仪式感：像拆礼物，而不是看物流
- 对照感：让顾客看到「我的参考图 → 最终成品」的呼应
- 传播点：页面适合截图分享朋友圈，为抖音号/直播间导流

- [ ] 作品完成后上传几张图（建议 3~9 张）
- [x] 抖音视频以「跳转链接」为主（✅ 已确认 v0.3：作品页放跳转按钮，跳抖音看完整视频）
- [ ] 是否需要「电子收藏证书」类元素（作品编号 + 日期）
- [ ] 设计参考网站/小程序链接（商家已有参考，待提供）
